## 2. 源码还原工具

### 2.1 extract-sources.js 工作原理

这是整个项目的核心工具，用于从 Source Map 文件中提取原始源码。

**Source Map 基础原理**：
Source Map（`.map` 文件）是 JavaScript 打包工具（Webpack/Bun 等）在编译时生成的映射文件，包含：
- `sources`：原始源文件路径列表
- `sourcesContent`：对应每个源文件的完整代码内容
- `mappings`：编译后代码与原始代码的位置映射

**提取流程**：
```javascript
async function extractSources() {
  // Step 1: 加载 58MB 的 cli.js.map 文件
  const rawMap = JSON.parse(fs.readFileSync('package/cli.js.map', 'utf8'));
  // rawMap.sources.length ≈ 4756 个文件

  // Step 2: 遍历每个源文件
  for (let i = 0; i < rawMap.sources.length; i++) {
    const sourcePath = rawMap.sources[i];        // 文件路径
    const content = rawMap.sourcesContent[i];    // 文件内容

    // Step 3: 路径规范化（4 步清洗）
    let relPath = sourcePath
      .replace(/^.*node_modules\//, 'node_modules/')  // 保留 node_modules 相对路径
      .replace(/^webpack:\/\/\//, '')                  // 去除 webpack:/// 前缀
      .replace(/^webpack:\/\//, '')                    // 去除 webpack:// 前缀
      .replace(/^\/?\.\.\//, '')                       // 去除相对路径 ../
      .replace(/\?.*$/, '');                           // 去除查询参数

    // Step 4: 安全处理（防路径遍历攻击）
    relPath = relPath
      .replace(/^\/+/, '')           // 去除前导斜杠
      .replace(/\.\.\//g, '_dotdot_/'); // 将 ../ 替换为安全字符串

    // Step 5: 写入文件
    fs.mkdirSync(path.dirname(fullPath), { recursive: true });
    fs.writeFileSync(fullPath, content, 'utf8');
  }
}
```

**输出分类**：
- `restored-src/src/` → Claude Code 源码（TypeScript）
- `restored-src/node_modules/` → 依赖库源码
- `restored-src/__webpack__/` → Webpack 运行时代码

```typescript
  }
```

### 6.1 工具池架构（tools.ts，389 行）

```typescript
// 核心工具获取（根据运行模式动态调整）
export const getTools = (permissionContext: ToolPermissionContext): Tools => {
  // SIMPLE 模式（CLAUDE_CODE_SIMPLE 环境变量）
  if (isEnvTruthy(process.env.CLAUDE_CODE_SIMPLE)) {
    return filterToolsByDenyRules(
      [BashTool, FileReadTool, FileEditTool],
      permissionContext
    );
  }
  // 标准模式：30+ 工具
  // REPL 模式：隐藏原始工具（已在虚拟机中可用）
  // Coordinator 模式：添加 AgentTool/SendMessageTool
};

// 工具池最终组装（内置 + MCP 工具合并）
export function assembleToolPool(
  permissionContext: ToolPermissionContext,
  mcpTools: Tools
): Tools {
  const builtInTools = getTools(permissionContext);
  const allowedMcpTools = filterToolsByDenyRules(mcpTools, permissionContext);
  // 按名称排序保持提示缓存稳定性
  const byName = (a: Tool, b: Tool) => a.name.localeCompare(b.name);
  return uniqBy(
    [...builtInTools].sort(byName).concat(allowedMcpTools.sort(byName)),
    'name'
  );
}
```

### 12.1 权限模式


### 12.2 权限规则分层

```
权限决策流程（优先级从高到低）：
1. alwaysDenyRules    → 无条件拒绝
2. alwaysAllowRules   → 无条件允许
3. alwaysAskRules     → 强制询问用户
4. PermissionMode     → 模式默认行为
5. 工具自身 checkPermissions() → 工具特定逻辑
```
